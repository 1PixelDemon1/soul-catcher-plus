# Soul Catcher Plus 0.2.0

Release date: **2026-10-27**. Target: **Minecraft Java 1.20.1 / Forge 47.4.28 / Java 17**. Release tag: `v0.2.0`. Artifact version: `0.2.0+1.20.1`.

This pre-1.0 update adds quick companion controls, persistent favorites, recall energy returns, and ownership-based support for mobs summoned by companions. It also fixes intermittent following and broadens spectral rendering support.

## Following and quick controls

Companion following now schedules path updates with its own goal timer and requests movement when the goal starts. This removes the global-tick parity condition that could prevent a running follow goal from updating its path.

- **O** opens the full collection.
- **Hold R** opens the command wheel. Hover an active companion, move to follow/wait/guard/recall, then release R to issue that individual order.
- Release in the center or outside the command ring, press Escape, or lose window focus to cancel.

Both bindings can be changed in Minecraft's Controls settings, including supported mouse bindings. They replace Shift + right-click menu opening. Menus and orders work without holding a scythe; creating a new summon still requires a scythe and applies its existing tier limit and energy cost.

The wheel does not pause the world. It displays soul energy, active companion names, current HP, and orders. Unloaded active companions show unknown health; recalling them invalidates their reservation without loading chunks. Individual wheel requests do not change the collection's selected species or group-command scope. The full collection retains its pause behavior for unpublished singleplayer worlds.

## Favorites and spectral rendering

Each species card has a favorite control. Favorites apply to all captured forms of that species and sort ahead of other cards, preserving capture order within each group. The flag is stored with the player's collection and survives saving; toggling it does not spend energy or change commands, selection, or active summons.

Spectral buffers are now supplied at the entity-dispatcher render call rather than rerendering through `RenderLivingEvent`. This includes compatible GeckoLib entity renderers and other paths that bypass that event. Ordinary entities retain their original buffers; departure echoes keep their existing fade, and nested dispatched entities avoid repeated tinting. Renderers that acquire their own buffers, custom materials/layers, or shaders may still need an integration. No third-party animation library is required by the base mod.

## Recall energy

A living, loaded root companion returns **`floor(current HP / 2)`** energy on recall. The minimum is **zero**: 1 HP returns 0, 10 HP returns 5, and 19 HP returns 9. This uses actual current health, not captured maximum health or the original summon price.

The same rule applies to individual, group, and automatic recalls. The active reservation is invalidated before integration callbacks to prevent duplicate returns. Dead, missing, or unloaded companions grant no refund because valid current health is unavailable. Recalling never loads a chunk solely to calculate a refund.

The summon and victory formulas remain unchanged: `ceil(captured max HP * 2)` for summoning and `floor(max HP / 2)` for credited victories, each at least one. Minion children have no independent refund.

## Mobs summoned by companions

Recognized Mob descendants inherit their root companion's player allegiance, permitted combat target, spectral appearance, and cleanup lifecycle. The default resolver follows explicit `TraceableEntity`/`OwnableEntity` creator links, including nested chains. It does not adopt nearby mobs based on location or spawn timing.

Children keep native movement and attack goals while independent target selection is replaced. A waiting root clears their inherited combat target. Their enemy kills credit the player, while the children themselves cannot become collection entries, consume scythe slots, or grant loot, XP, soul energy, or recall refunds. An owned child's scythe interaction selects its root collection entry.

Minion links persist by root UUID. For Vex, the native owner and idle origin are restored when the root is loaded, without extending the native limited lifespan. A valid unloaded root leaves its child idle. Root recall, death, or permanent removal dismisses loaded descendants; invalid unloaded descendants are rejected on their next load. Permanent root removal without a normal death event also ends its reservation with the usual defeat cooldown and no refund.

Custom integrations can implement `SoulAdapter.summoner`, `configureMinion`, and `tickMinion`, or call `SoulMinions.attach(child, creator)` on the server. These remain experimental APIs. Unknown/cyclic/cross-level creator chains, independent Brain logic, and custom spell or projectile systems can require adapters. An old unmarked Vex that already lost its native owner in a save cannot be safely adopted retroactively; use newly created minions when inspecting this feature.

## Developer-only QA support

With development test sources enabled, `/soulcatcherqa --all` creates one constructor-default capturable form per registered Mob type in small server-tick batches, preserving known entries and selection and reporting skips. It shares the 4096-entry collection bound and does not enumerate every visual variant or spawn-dependent state. Temporary samples are not inserted into the world or AI-ticked. The command and its sample helpers are excluded from the normal release JAR.

This is a population tool, not proof that arbitrary mod constructors or adapters are safe or compatible. The existing bare sample command remains available in that development setup.

## Installation and save compatibility

Install `soulcatcherplus-0.2.0+1.20.1.jar` on both client and server. The base mod requires Minecraft 1.20.1, Forge 47.4.28, and Java 17, with no Mowzie's Mobs or GeckoLib dependency. The existing optional Wroughtnaut integration targets **Mowzie's Mobs 1.8.2 for 1.20.1** and **GeckoLib 4.8.3 for Forge 1.20.1**, installed separately.

This release uses **network protocol 6**; 0.1.0 used protocol 4. Update client and server builds together. Do not mix these releases in multiplayer.

Existing collection entries, health pricing, UUID ownership, energy, and active reservations retain their saved format. Favorites use an optional `Favorites` string list; older saves load with none. Persisted minion links are additional entity data. No existing appearance must be recaptured just to add favorites. See [API documentation](../API.md), the [README](../../README.md), and [0.1.0 release notes](0.1.0.md) for the retained core mechanics.

## Known limitations

Balance and public interfaces remain provisional. This release does not promise universal mod compatibility. Native AI, creator exposure, custom renderers, extra shader/layer paths, and shared encounter systems can require dedicated adapters. Minion support is ownership-based and covers recognized Mob descendants rather than every possible spell, projectile, or custom summon implementation.

Two-client multiplayer, long-running saves, all third-party creature types, and every exceptional cleanup or rendering path have not received comprehensive release validation. The inherited scythe tiers, boss-bar discovery heuristic, collection limits, and other 0.1.0 constraints remain in effect.
