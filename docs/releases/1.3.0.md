## New since 1.3.0-prerelease: Soul Seal

Use a **Soul Seal** on your active personal companion to save its current
adapter-supported state back into that collection entry, including supported
equipment and current maximum health. Future summons use the updated snapshot;
the summon cost is recalculated from saved maximum health. The entry's collection
name and active identity are preserved. The seal does not transfer ownership or
capture an unrelated mob, pylon guardian, or summoned child into your collection.

One seal is consumed when the saved snapshot changes, except in Creative. An
unchanged or rejected update consumes nothing. The crafting recipe uses four
gold nuggets, four bones, and soul sand. Snapshot sanitization still removes
temporary potion effects, live identity/location, and Soul Catcher ownership data,
and sets captured equipment drop chances to zero. Custom adapters
determine which native/mod-specific state can be saved; this is not universal
support for every inventory or capability.

Legacy experimental `SealedEquipment` data is merged into the normal saved
snapshot when loading an entry. `SaddleItem` is included in equipment previews.
This fallback is not a general cross-version world migration guarantee.

## Added since stable 1.2.3

- **Soul Pylon:** insert a scroll and charged cage for a saved block-bound guardian,
  separate from personal companion slots. Standard Guard-compatible mobs and Raven
  are eligible; custom brains are not automatically supported. New summons require
  the owner online. No chunk is force-loaded, and an unloaded guardian is not
  treated as dead or replaced. Pylon slots are edited through the menu, not hoppers.
- **Raven stockpiles:** a pylon Raven collects nearby items and deposits them by its
  anchor, preferring a safe adjacent hopper and avoiding its own stockpile. It
  retains cargo while the anchor is unloaded. This role does not collect soul
  remnants; a personal Raven retains owner delivery.
- **Soul Projector / Quartz Soul Projector:** display a detached decorative scroll
  preview with size (25–400%), angle, color, opacity (10–100%), and rotation controls.
  The display has independent settings and is neither spawned nor AI-ticked.
- **Soul Transfer Altar:** spend paper and the displayed cage-energy cost to copy a
  collected form into a shareable scroll, keeping the original collection entry.
- **Soul-Fueled Furnace:** use one soul energy per furnace smelting operation,
  retaining recipe-driven cooking time/experience and saved paid progress.
- **Soul Energy Bow:** spend 10 energy per soul-bolt shot, without arrows.
- **Soulbound Hoe:** sneak-use bone-meal behavior for five energy per successful
  application; unsuccessful fertilization returns its payment.
- **Soul Sacrifice Totem of Undying:** a held reusable totem spends 500 energy on
  eligible revival when vanilla totem protection has not already handled the hit.
  Bypass-invulnerability damage remains excluded.

Equipment uses the first offhand/hotbar cage that can pay its whole cost, without
pooling cages; ordinary companion-summoning cage selection is unchanged. Bow/hoe
smithing requires the vanilla Netherite Upgrade template on 1.20.1/26.3; older
platform recipes use their template-free smithing format.

Use wheat seeds on your active Raven to unlock **Long-tailed Tit**, or a note
block on your active Shaman to unlock **Hatsune Miku**. These are additional
collection forms retaining the existing companion roles. Forgotten Soul geometry
and materials are refreshed. Soul color/opacity are saved per owner and shared
with observers; the picker keeps its 10–100% range and 42% default. Recognized
flying souls hold position during Wait; ordinary ground mobs retain gravity.

The optional English/Russian Patchouli guide has **25 entries and six categories
per language**. Older-platform examples are Patchouli 53.3/77/85 for
1.16.5/1.19.2/1.20.1. The 26.3 JAR includes translated text resources, but no working
published Forge Patchouli build or guide crafting is claimed there.

## Fixes after the prerelease

- Encode empty Pylon/Projector item slots correctly with the native 26.3 codec.
- Fix startup with default 26.3 mipmap settings: ten projector/pylon/altar block
  sprites are doubled from 8×8 to 16×16 with nearest-neighbor sampling, preserving
  their pixel-art appearance and UV layout.
- Fit the displayed soul cage inside the Soul-Fueled Furnace model.
- Check the originating connection before accepting owner-appearance updates, so
  an obsolete client session cannot update the current appearance cache.
- Use native minimum/maximum build height for Raven pylon drop positions on
  1.19.2/1.20.1/26.3, allowing valid deliveries below Y=0.

## Installation and scope

Install the matching Minecraft core JAR on both client and server. Protocol **17**
replaces stable 1.2.3's protocol 13; use the same release on both sides. Protocol
equality does not permit connections between different Minecraft versions.

The core requires neither creature mods nor animation libraries. Dedicated
integrations are distributed separately in Compat, with creature mods and their
libraries installed separately. No universal support for custom AI/renderers,
creature integrations on 26.3, rollback, or cross-Minecraft world migration is
promised. Keep backups and separate profiles for different game versions.

## Artifacts and validation

Artifact names are `soulcatcherplus-1.3.0+<minecraft>.jar` and matching
`-sources.jar` files for the four platforms. Only runtime JARs are installed.
The prepared core set contains four runtime JARs, four sources JARs, and
`SHA256SUMS.txt`; the combined release record includes `archive-audit.json` and
`startup-audit.json`.

All eight fresh core/addon `build -x test` packages passed. Audits checked all
16 runtime/sources archives for ZIP integrity, metadata/version ranges, class
versions 52/61/61/69, JSON and recipe/model resources, Mixin entries, and exclusion
of QA, Jabel, JUnit, and cross-bundled core/addon code. Final source review included
the slot-encoding, rendering/session, Raven-height, and 26.3 mipmap corrections.

All eight ordinary installed-production-client profiles passed startup with the
final packaged runtime bytes; launch hashes match release assets. Clients loaded
resources, sound, and atlases, then closed normally with exit 0 without entering
worlds. Core clients used Patchouli 53.3/77/85 on 1.16.5/1.19.2/1.20.1; 26.3 used
the core alone. The corrected 26.3 block atlas loaded with its default four mip
levels. Addon dependency profiles are listed in its release notes.

The 1.16.5 addon profile reports nonfatal invalid transparent PNGs from Twilight
Forest's own JAR. Successful startup does not certify error-free external logs.
No new dedicated-server, automated tests, GameTests, UI automation, gameplay, or
multiplayer verification ran. Client startup does not verify seal state/equipment,
guardian lifecycle, terrain protection, combat, devices, or visuals in-game.
Previous prerelease/1.2.3 results remain historical evidence only.
