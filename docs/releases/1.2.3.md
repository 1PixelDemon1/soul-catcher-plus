## Committed Aggressive combat

An Aggressive companion with a valid target can continue its fight until the
companion exceeds the hard owner-distance threshold: **64 blocks by default**, or
the adapter's larger range, such as **100 blocks for Compat's Ice and Fire dragons**.
Beyond that distance it abandons combat and attempts to return through the common
teleport/return rules.

Idle following and new-target acquisition keep the ordinary adapter range,
**40 blocks by default**. The local Aggressive search radius remains 16 blocks;
Follow's combat limits are unchanged. This extends commitment to an existing
fight rather than increasing how far away new targets are selected.

The Ender Dragon's separate 32-block flight-destination clamp no longer restricts
Aggressive combat with a target. Idle/Follow flight keeps its compact orbit;
fireball range and cooldown are unchanged.

## Shared summon and teleport placement

Summoning and owner teleportation share a size-aware search of 16 angular positions
at vertical offsets **0, +1, -1, +2, -2**. Clear candidates that do not overlap the
owner are preferred. If no clear candidate exists, a bounded fallback can overlap
blocks. Air and water no longer require solid support.

The full entity bounding box must remain inside loaded chunks, the world border,
and build-height limits. No chunk is loaded solely to find a placement. A search
can still fail if no candidate satisfies those bounds.

Owned souls and recognized minions are immune to **in-wall suffocation damage**.
This does not add fall-damage or drowning immunity, clear nearby blocks, or make
every air/water destination harmless for every creature.

The English/Russian orders chapter covers Follow, Aggressive, Wait, Guard,
Teleport, Recall, and manually directed Attack. It explains target commitment,
the guard post, Teleport moving that post, recall, and scythe-directed attacks

processor field mappings are supplied to reobfuscation instead of aliasing a
non-private field. The earlier release tags and original/hotfix artifacts remain
unchanged. Its previous successful checks are historical, not new 1.2.3 validation.

## Installation and scope

Install the matching core on both client and server. Use the exact-version Compat
build on both sides for dedicated integrations, with creature mods/libraries
installed separately. The core remains independent of addon sources and runtime
dependencies. Use separate game-version profiles/worlds and backups; no universal
world migration is supplied.

Compat adds owned Siren appearance/charm corrections on version-matched
1.16.5/1.19.2/1.20.1 Ice and Fire builds. No Ice and Fire or
other creature integration is certified for 26.3. A working published Forge
Patchouli build on 26.3 is not claimed.

## Validation

All eight fresh core/Compat `build -x test` packages passed archive audits and
ordinary installed-production-client startup checks before publication. The
clients used the exact frozen runtime JARs, completed sound/atlas loading, and
closed normally without entering worlds (exit 0). Final source/native-API review
found no actionable issues after the 26.3 relocation/build-height fixes.

Core clients used Patchouli 53.3/77/85 on 1.16.5/1.19.2/1.20.1 respectively;
26.3 used the core alone. Compat profiles used the matching dependencies listed
in its release notes; 26.3 used only core/addon. Book resources loaded where
Patchouli was available. Existing external Twilight resource warnings and offline
Realms authentication warnings remain; successful startup does not mean clean logs.

Audits verified ZIP integrity, metadata/Forge versions, class versions 52/61/61/69,
JSON/Mixin resources, and absence of QA, Jabel, JUnit, annotation processors, and
bundled addon/third-party code. Both guide languages retain 18 entries across
five categories, the 12-line page limit, and four double-recipe blueprint pages.
Each project's `build/releases/1.2.3` contains four runtime JARs, four sources
JARs, the audit report, and `SHA256SUMS.txt`.

No automated tests, GameTests, UI automation, gameplay, multiplayer, or manual
combat verification ran. No fresh 1.2.3 dedicated-server startup was performed.
These checks establish packaging, resource loading, and client startup, not
in-game combat, placement, Siren behavior, or universal mod compatibility.
