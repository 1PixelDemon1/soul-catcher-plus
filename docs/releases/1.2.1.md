# Soul Catcher Plus 1.2.1

Release date: **2026-11-10**. This **core-only release** adds vanilla boss companion
controllers, a production scroll command, guide/localization improvements, and
repository cleanup across all four maintained Forge platforms. Compat is not
updated or released with 1.2.1; its compatibility with this core was not verified.

## Built-in vanilla boss companions

The core adds dedicated adapters/controllers for owned vanilla **Wither** and
**Ender Dragon** companions. They use the common command, targeting, ownership,
return, recall, and recovery rules while retaining their native entity types.
These corrections are built into the core, without requiring an external addon.
Naturally spawned bosses and unrelated entity types keep their encounter rules.

For **Wither**, the inspected controller directs all heads at the approved combat
target, retaining native skull entities, side-head firing cadence/range checks,
armor/defenses, healing, and head animation. Wait holds position; other idle modes
fly toward the owner or guard point. Random idle shots, inherited spawn
invulnerability/explosion, and damage-triggered terrain destruction are disabled.
Owned skull explosions retain enemy damage while excluding terrain damage and
allied explosion knockback.

For **Ender Dragon**, the native multipart body, flight integration, animations,
fireballs, and breath remain. An entity-local phase controller replaces encounter
waypoints with owner/guard flight, attack approaches, and orbits. Wait stops
movement/attacks. Fireballs use an 80-tick cooldown. Contact damage/knockback is
limited to the approved target; incoming damage follows ordinary living-entity
rules while retaining reduced damage on non-head parts. Native block destruction
and End-crystal healing are disabled.

The soul dragon is detached from the End encounter manager, whose dragon searches
exclude companions rather than adopting/deleting them as the encounter boss.
Companion death follows soul cleanup/recovery, without encounter XP, exit portals,
or fight completion. Breath clouds persist a root UUID, require a loaded living
canonical companion before applying effects, discard orphaned clouds, and exclude
allies before potion processing. Their harm effect damages undead enemies rather
than healing them, preserving caster attribution.

Each port uses its native APIs/Mixins; fresh build and dedicated-server startup
checks passed. Those checks do not verify boss combat or protection behavior in
gameplay. The full-size dragon still needs suitable summon/teleport space.
Modified boss AI, shared encounter mods, and other third-party boss types can
require their own adapters; universal boss-mod compatibility is not promised.

## Production scroll command and advancement

Add the operator command:

```text
/soulcatcher scroll <namespace:entity|namespace@entity> [player]
```

It requires permission level **2** and accepts entity IDs from the live registry,
including installed mods. Without a recipient it targets the player issuing the
command; console use needs an explicit player. The optional recipient uses a
single-player name/selector. Examples:

```text
/soulcatcher scroll minecraft:wither
/soulcatcher scroll minecraft@ender_dragon @p
/soulcatcher scroll soulcatcherplus:soul_shaman PlayerName
```

The command grants one scroll for the type's **default form**, selecting ordinary,
Boss, or Forgotten classification through the shared rules. An unspawned sample
validates that the registered type can produce a mob; it is not added to the world,
summoned as a companion, or inserted into the bestiary. Unknown/unsupported types
and constructor failures are reported. A full recipient inventory refuses the
grant instead of silently deleting overflow. Creating/holding the scroll does
not grant soul energy or bypass normal costs when later summoning its soul.

The existing `/soulcatcher energy <amount>` command remains documented alongside
the new command. Both are production commands, available without the development
QA flag. QA-only commands are deliberately omitted from the player guide.

A new **Forgotten Soul** advancement triggers when a Forgotten Soul Scroll enters
the inventory. Its condition is obtaining the item, not opening it or summoning
the contained companion.

## Localization and command interface

Russian soul/enchantment names and the English/Russian guide text are revised.
The command wheel now sends a translation key for an unnamed built-in companion,
allowing each client's language to determine its displayed name. Captured/custom
names remain literal rather than being replaced by a translated default.

Collection group-order highlighting considers loaded companions that accept the
standard behavior modes. Raven/custom-brain entries and unloaded companions no
longer suppress a valid common-order highlight. Standard mode buttons reflect
eligible recipients; Recall/Teleport retain their separate lifecycle/action roles.

This wheel payload change uses **network protocol 13**, replacing protocol 12
from 1.2.0. Update clients and servers together. Matching protocol values across
different Minecraft versions still do not enable cross-version connections.

## Revised optional guide and repository cleanup

The optional Patchouli book is rewritten as an in-world field guide, with exact
balance values left for players to discover. Each language has **18 entries**
and **five categories**: **46 localized content JSON files**, plus the book
definition. The separate commands/debugging chapter explains production energy
and scroll commands, permissions, ID forms, recipients, and examples.

The Drawings entry uses four recipe-only pages, two recipes per page and **four
recipes per spread**. One spread covers iron/diamond equipment; the next pairs
netherite upgrades with Supreme recipes. Prose stays in other entries so
translation length does not push recipes onto different spreads. Recipe pages
reference the real recipe IDs, and the replacement-book recipe has its own entry.

Patchouli remains an optional separate installation. Existing baselines are
53.3/77/85 for 1.16.5/1.19.2/1.20.1. Packaged book resources passed structural,
pagination, and recipe-ID checks on all four builds; fresh Patchouli client loading
was confirmed on 1.16.5. No fresh 1.19.2/1.20.1 client-book result is claimed for
this release. Compatible Forge Patchouli support on 26.3 is not claimed. Retained
book resources on that port do not establish an available working integration.

Repository cleanup removes obsolete concepts, duplicate/intermediate model inputs,
generated previews/frame sheets/reports, and unsupported legacy 1.16.5 automated
test sources/dependency. Approved authoring inputs and runtime assets remain;
asset workflows are consolidated in `docs/ASSETS.md`. Build packaging uses committed
runtime resources rather than regenerating artwork. This cleanup is separate from
the gameplay changes and does not invalidate historical release records.

## Installation, compatibility, and validation

Install the core JAR matching the selected Minecraft version on both client and
server. Keep backups and separate game-version profiles/worlds. No universal
world or custom entity-state migration is supplied. This release updates only the
core. The existing separate Compat addon was neither updated nor validated;
do not assume that its exact-version dependency accepts core 1.2.1.

All four fresh `build -x test` runs succeeded. Read-only archive inspection passed
ZIP integrity, class versions **52/61/61/69**, metadata/version/Forge requirements,
JSON parsing, boss-controller/Mixin presence, localized guide content/pagination,
real recipe references and spreads, protocol 13, and the Forgotten Soul advancement.
Runtime JARs contain no QA helpers, JUnit, Jabel, nested dependencies, or addon
classes. The 1.16.5 audit also excludes Java Record/runtime leaks.

All four ordinary dedicated servers reached **Done** in isolated new worlds,
then saved and stopped normally with **exit code 0**. The fresh 26.3 repeat passed
after the final native breath-Mixin redirect corrections. These were startup
checks without players, not gameplay or multiplayer tests.

The 1.16.5 development client launched with the QA flag, Twilight Forest,
Aquamirae, and Patchouli. Patchouli book loading, OpenAL/sound initialization, and
all texture atlases completed by **2026-11-10 22:39:35**. It was left open for the
user. The QA flag only made the manual command available; it was not executed.
Known external Twilight Forest missing texture/model/sound messages and a
development Realms `DONT_CRASH` authorization message remain; no Soul Catcher Plus
loading error was observed. No fresh client-startup claim is made for the other
three platforms in this release.

**No automated tests, GameTests, or UI automation were run.** In particular,
1.2.0's earlier persistence-unit results are historical evidence, not new 1.2.1
checks. Build/archive/startup success does not establish boss combat, friendly-fire
protection, terrain safety, End-encounter independence, loot rolls, multiplayer,
every translated page, or arbitrary mod compatibility in gameplay.
