# Soul Catcher Plus 1.0.0 — Forge 1.19.2 supplement

Release date: **2026-10-31**. Target: **Minecraft Java 1.19.2 / Forge 43.5.2 / Java 17**. Artifact version: **`1.0.0+1.19.2`**. Platform release identifier: **`v1.0.0+1.19.2`**.

This additive release brings the 1.0.0 core and combined integration addon to Forge 1.19.2. It extends the supported platforms of the [original 1.0.0 release](1.0.0.md); the existing `v1.0.0` tag and original release notes remain unchanged. The platform identifier belongs to the 1.19.2 source line, while `main` retains the primary 1.16.5 code and documents the additional platform. Validation of the original 1.16.5/1.20.1 artifacts does not validate these new files.

## Installation

Install the 1.19.2 core on both client and server:

- `soulcatcherplus-1.0.0+1.19.2.jar` — core, requiring no creature mod or animation library.
- `soulcatcherplus-compat-1.0.0+1.19.2.jar` — optional combined integration addon; install on both sides when its corrections are needed, with the **exact matching** core version.

Both artifacts declare Forge **`[43.5.2,44)`** and require Java 17. The previous development port's lower declared minimum of 43.2.0 is not retained. Creature mods and their own libraries must be installed separately for Minecraft 1.19.2; neither project JAR bundles them. Do not mix the 1.16.5, 1.19.2, and 1.20.1 builds in one profile, even though their feature versions and protocol numbers match. Fabric and NeoForge are outside this release.

## Included 1.0.0 features

The port includes the same 1.0.0 gameplay feature set as the other Forge builds:

- Persistent player-UUID soul collections with captured appearance forms, species favorites, detached rotatable/zoomable previews, scrolling, name/ID search, and confirmed deletion of one form. Deleting an active form first recalls it through the normal refund/cleanup rules.
- Iron, diamond, netherite, and Supreme scythes and cages. Base scythe limits are 1/2/3/4 and cage capacities are 150/400/1000/2000. Soul Capacity I–III increases cage capacity, Soul Harvester I–II increases victory energy, and Soul Slot I adds one slot per worn enchanted armor piece, up to eight companions with Supreme equipment.
- Remappable O collection and held-R wheel, requiring a soul scythe in either hand. Individual and group Follow/Aggressive/Wait/Guard/Recall commands, targeted attacks, and safe return attempts beyond 24 blocks remain available. Only the full collection pauses unpublished singleplayer worlds.
- Health-based capture/summon economics, transferable cage energy, spectral bodies and departure echoes, high-health soul highlighting, animated cage/scythe artwork, a dedicated creative tab, and five advancements.
- Generic ownership-based minion allegiance, inherited combat targets, persistent links, and root cleanup, with native master restoration and opt-in spawn attribution. Children have no independent slots, collection entries, loot, XP, soul-energy reward, or recall refund.

Core mechanics, recipes, and limits are detailed in the [original notes](1.0.0.md). The relevant version-specific difference is **netherite smithing without an upgrade template**: combine a diamond scythe/cage and netherite ingot. Cage contents survive upgrading. The 1.20.1 template requirement does not apply to 1.19.2.

## Integration addon and port-specific behavior

The optional addon supplies Wroughtnaut activation/appearance and area-attack ally filtering, Twilight Forest Snow Queen ice-crystal attribution and Lich clone/minion master links, and Aquamirae Cornelia music-cooldown handling. The Wroughtnaut soul profile is packaged only in the addon; its duplicate was removed from the core. The core retains generic ownership, rendering, commands, boss-bar discovery, music filtering, and public extension hooks without the addon.

These are source/API checks, not in-game verification of every creature or a promise covering every admitted dependency version. Install each third-party mod's own version-appropriate dependencies. Other Aquamirae implementations, including the separate 1.20.1 6.x/7.x lines, are not interchangeable with this hook.

The UI uses native 1.19.2 rendering APIs. Minion resolution uses supported explicit owner/summoner links because this Minecraft version has no `TraceableEntity` interface; unknown creator systems still require an adapter or explicit attachment. Music handling uses the native 1.19.2 music-manager API. A companion's identifiable boss music can be filtered without globally muting unrelated bosses; asynchronous or source-less controllers may need a dedicated integration.

## Upgrade and save compatibility

Back up the world and update both client and server, including any installed addon. This build uses **protocol 11**, replacing protocol 9 in the earlier 1.19.2 development port. Collection snapshots travel in parts of at most 32 rows and replace the displayed state only when fully assembled. Equal protocol numbers across different Minecraft versions do not enable cross-version multiplayer.

Compatible same-1.19.2 collection identities, captured forms, favorites, active reservations, and recovery data retain their ledger representation (schema 3). The collection remains attached to the player, while energy belongs to individual cages. **Old player-ledger energy is not converted into cage energy.** Cages in the offhand and hotbar participate; spending draws the whole summon price from one active cage, and rewards/refunds beyond available eligible capacity are lost.

No world or collection migration between Minecraft versions is supplied. Use separate profiles/worlds; the original release's similar item IDs do not make a newer world safe to open on 1.19.2. External integrations need the version-matched API and Minecraft classes rather than a JAR compiled for another platform. Older minions whose creator links were already lost cannot be reliably adopted retroactively; use a new summon for those links.
