# Soul Catcher Plus 1.1.0

Release date: **2026-11-08**. Artifact version: **`1.1.0+1.16.5`**. Target: **Minecraft Java 1.16.5 / Forge 36.2.42 / Java 8**.

This local release adds Forgotten Soul companions obtainable from rare chest loot, consumable soul scrolls, animated 3D cages, local soul appearance controls, persistent offline companions, and revised return/teleport commands. It updates the **1.16.5 core only**. The maintained 1.19.2/1.20.1 ports and the external compatibility addon do not receive a new release in this milestone. No GitHub publication or push is part of this preparation.

## Installation and compatibility

Install `soulcatcherplus-1.1.0+1.16.5.jar` on both client and server with Forge 36.2.42 and a Java 8 game runtime. The core requires no third-party creature mod or animation library. Gradle/javac use Java 17 and compile-only Jabel 1.0.0 to emit Java 8 bytecode; Jabel is not a runtime dependency.

Protocol **12** adds Teleport commands, replacing protocol 11 from 1.0.0. Update both sides together. This release provides no new builds for other Minecraft versions and no cross-version world migration.

Mod-specific corrections have moved out of this repository into an external integration project. Core builds, ordinary development launches, and playtest archives no longer load or package compatibility-addon sources/JARs. Generic adapters, events, rendering hooks, ownership, and lifecycle APIs remain available. **Do not assume the 1.0.0 addon works with 1.1.0:** earlier addon metadata requires an exact core version, and this release does not validate or update it. Complex third-party creatures can still need a separately maintained adapter.

## Rare Forgotten Souls

The additive Forge loot modifier gives each **root loot-table generation whose path starts with `chests/` a 2% chance** to append one Forgotten Soul Scroll. All namespaces participate, including modded chest tables that follow that path convention. A successful roll selects **Soul Raven or Soul Courier equally**, storing the selected type explicitly in the scroll. At most one scroll is added by this modifier per generation; it does not replace ordinary loot.

Already generated chest inventories are not rerolled. Modded chest tables using other paths are not automatically included, and non-chest paths such as entity drops are skipped before drawing random numbers. Nested helper tables do not gain extra rolls. The chance is editable through `data/soulcatcherplus/loot_modifiers/forgotten_souls.json`; valid values are finite numbers from 0 through 1. The Forge modifier list uses `replace: false` to preserve other registrations.

Forgotten Souls cannot be unlocked by ordinary scythe capture. Use the typed scroll to add the companion to the collection, then summon it through the normal cage-energy, species, equipment-slot, and recovery rules.

**Soul Raven** has **4 HP** and runs passive collector AI. It searches loaded surroundings within 20 blocks of its owner for eligible dropped items and their owner-bound soul remnants, picks up the original entities as cargo, and carries up to eight entities at a time. It returns items through normal pickup handling and collects delivered souls through the same server-authoritative collection path used by manual capture. An eligible hotbar/offhand cage is still required for soul collection, but a held scythe is not required for Raven delivery.

The Raven respects pickup delay and item ownership. Uncollected inventory overflow remains in the world; creative overflow is protected from vanilla creative insertion discarding the remainder. Cargo is saved as native passengers during chunk unload and released on death, recall, or stale-entity cleanup. Failed dismounts are handled without deleting the cargo's only vehicle. Idle Ravens perch on the owner's shoulder, with flight/perch animations and glowing eyes; the owner's perched Raven is hidden in first person. Ordinary combat/movement modes do not replace its collector AI, while recall and manual Teleport remain available.

**Soul Courier** has **8 HP** and acts as a passive portable access point to an Ender Chest. Each interacting player sees **their own existing 27-slot Ender Chest**, rather than the summoner's inventory or shared Courier storage. The chest opens with a lid animation and sounds, and the Courier stops walking while viewed. Interaction also works while holding a soul scythe. Closing/leaving the menu or losing the Courier does not transfer the stored inventory into the mob.

## Soul scrolls

Soul, Boss, and Forgotten Scrolls have distinct native **16×16** sprites. The ordinary Soul Scroll defaults to a **Pig**, the Boss Soul Scroll to a **Wither**, and the creative tab has explicit Raven and Courier Forgotten variants. A bare Forgotten Scroll defaults to Raven; chest loot always stores the chosen type. The old `courier_soul_scroll` ID is retained for development-save compatibility but hidden from the creative tab.

Right-click from either hand to unlock the contained form. Successful use creates a new player collection identity and consumes one scroll, **including in creative mode**. Known forms, invalid/unavailable types, and a full collection preserve the item. Unlocking requires neither a scythe nor cage, grants no energy, and is not a combat-capture advancement/event. Summoning afterward retains the normal costs and requirements.

The public `SoulScroll.containing(SoulEntry)` helper stores a sanitized captured-form payload, choosing Forgotten for Raven/Courier, otherwise Boss for at least 150 maximum HP, and ordinary Soul Scroll for other forms. It does not carry the original ledger UUID, active summon, or recovery timer. This helper does not add a player-facing collection-export action. Ordinary/Boss Scrolls have no new recipe or survival loot source in this release.

Creative-scroll use is registered through the common `SoulEvents` handler rather than subscribing the item class itself. This avoids the event bus reflecting over the item's client-only tooltip signature on a dedicated server. Source and bytecode inspection checked the correction; a dedicated server was not launched.

## Commands and persistence

The collection and command wheel gain **Teleport** for one companion or the group. It requires a held scythe and addresses loaded root companions in the current dimension only; unavailable entities are not retrieved by loading chunks. Safe destination checks preserve entity identity, HP, energy, and behavior mode, clear attack/navigation, and move a Guard anchor to its new position. If suitable space is unavailable, the action can fail or report partial success.

For standard-brain **Follow/Aggressive** companions, combat now stays within **40 blocks of the owner**. Beyond that distance they abandon combat and path back, remaining in return mode until within four blocks or successfully teleported. Beyond **64 blocks**, or after **100 game ticks without at least one block of further return progress**, they attempt a safe teleport. Failed searches retry at most once per 20 ticks. This replaces the previous 24-block forced-teleport policy. Aggressive acquisition still requires a visible eligible target within 16 blocks of the companion, now bounded by the 40-block owner area. Custom-brain companions such as Raven retain their own movement policy.

Wheel recipients lock after selection, so crossing another sector or paging cannot silently change the destination of an order. Return the pointer to the center to clear the lock before choosing another recipient/page. If the selected companion disappears, commands are disabled rather than redirected. Collection mode buttons highlight the current order; in group scope, a highlight appears only when all active entries share that order.

Logout no longer recalls active companions. Their ledger UUIDs, native saved state, health, position, orders, minions, and cargo remain across logout/reload. Valid owned entities and their independently ticked non-player passengers pause their native tick while the owner is offline, including fuse/lifetime timers, then loaded companions resume when the owner returns. Stale reservations still reach normal cleanup. Player death and dimension changes retain the existing recall rules; no replacement summon charge is imposed merely for logging back in.

## Appearance and models

The palette button in collection O opens a local soul appearance editor with HSV controls, HEX RGB input, a live detached preview, reset, and **10–100% opacity**, defaulting to **42%**. Closing the editor saves the client setting. It affects summoned souls visible to that client, including departure echoes; it does not synchronize a player's color to others or recolor ordinary creatures/resource items. Custom rendering pipelines can still require visual integration.

Synced companion and minion names use `PlayerName's CreatureName`, retaining captured names without stacking owner prefixes after reload/nickname changes. Floating soul nameplates are hidden while the underlying metadata remains available to other mods.

All four cage materials now use animated native 3D meshes in first/third-person hands, with chain grips, translucent glass, orbiting/bobbing souls, and material-specific details. Inventory and other non-hand contexts retain their sprites. Editable Blockbench models, pixel maps, and export scripts accompany the Raven, Courier, cages, and scroll artwork.
